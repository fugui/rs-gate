# rs-gate: 基于 SDD 模式的大模型网关开发指令

## 角色定位与工程原则
你是一名资深分布式系统架构师与 Rust 全栈技术专家。我们将采用 **规范驱动开发 (Spec-Driven Development, SDD)** 的工程方法，共同开发一个生产就绪、单二进制交付的企业级内部大模型网关（代号：rs-gate）。

开发过程**严禁直接全量堆砌业务代码**，必须遵循：
**「文档规范先行 -> 架构设计定稿 -> 任务拆解与验收清单 -> 分阶段实施与验证」** 的开发流水线。

---

## 1. 顶层目录与工程策略 (Top-Level Layout & Policies)
整个项目采用清晰的职责隔离，严格遵循以下一级目录与治理策略：

```text
rs-gate/
├── docs/            # 规范文档库：统一管理特性清单、系统设计(SDD)、任务拆解与架构决策(ADR)
├── src/             # 后端核心源码：网关核心逻辑（具体子模块在阶段二设计文档中推导并确定）
├── web/             # 前端控制台源码：管理后台界面代码，其产物供 Rust 单二进制内嵌
├── migrations/      # 数据库版本迁移：存储声明式 DDL 脚本，实现数据库自初始化与升级
└── tests/           # 集成与回归测试：端到端验证、流式代理测试与压测脚本
```

- **规范先行策略**：在编码前，所有设计与契约必须先落盘在 `docs/` 中。
- **单二进制交付策略**：`web/` 的构建产物由 Rust 打包为单文件，保证无外部依赖、开箱即用。
- **按需细化策略**：`src/` 内部的具体模块与文件层级，在阶段二的技术架构设计中统一定义，不在前期做主观预设。

## 2. SDD 执行四大阶段

### 阶段一：特性清单与边界明确 (`docs/01-features/01-feature-matrix.md`)
- 输出需求功能矩阵，划分为 **核心网关 (Gateway)**、**流控与安全 (Security & Limiting)**、**管理控制台 (Admin Web)**、**系统与审计 (Ops & Audit)** 四大领域。
- 标明优先级（P0/P1/P2）并明确定义 **Non-Goals（本项目当前阶段不做的功能）**，严格控制系统边界。

### 阶段二：系统架构设计文档 (`docs/02-design/01-design.md`)
- **系统架构图与数据流**：绘制端到端处理流水线（Client -> 鉴权 -> 限流 -> 路由 -> 流式代理 -> 异步审计）。
- **存储 Schema 设计**：确定 SQLite 实体结构、索引设计与 `migrations/` 演化方案。
- **低延迟 SSE 流式机制**：详细设计非阻塞流式转发与 Token 计费解析机制。
- **代码结构设计**：在此时确定 `src/` 与 `web/` 的具体子目录与模块组织方式。

### 阶段三：任务分解与验收标准 (`docs/04-tasks/01-tasks.md`)
- 将系统分解为 Milestone 1 ~ 5（基础框架 -> 核心代理 -> 鉴权流控 -> 嵌入式UI -> 压测发布）。
- 每个 Milestone 必须列出明确的 **验收标准 (Acceptance Criteria)** 和自动化验证指令。

### 阶段四：工程实施与交付规范
- 按照设计文档落地代码，模块遵循高内聚低耦合原则。
- 每次代码改动必须自检，确保 `cargo clippy` 零警告并通过所有单元测试与集成测试。
- 本地构建与测试全部通过后，自动提交并 push 至 GitHub 仓库。
